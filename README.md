上传了 **量子狗算狗Inc.**（指我（产品经理）与[智谱清言](https://chatglm.cn)（主开发程序员）） 出品的 mga_scan、mga_scan_v2、test 等脚本。

其中 mga_scan 是自动化部署所有地球到木星的探测序列（是的你没看错！包含 EJ、EEJ、EVEEJ、EVVEJ、EMJ 等全部中间借力不超过 4 个的 121 个序列）并横评的脚本，发射窗口位于 2025-2035 之间。从此你再也不用傻乎乎地为每一个序列写专门的脚本了，再也不用羡慕不开源的 NASA 的 STOUR 了！

这脚本有以下特性：

参数全自动：TOF 包络、发射 v∞、飞掠高度、总时长帽全部按序列结构动态生成，长序列不会被子虚乌有的边界冤死；哪怕 pykep 换了内部变量排布，布局解析也能按边界特征自动重新认领，不挑版本

公平赛制：每个序列自己的时长帽（min(2×自身下界和， 9.5年)），快的和慢的不在一个赛道上瞎比；谁没收敛自动追加种子重赛，不给摸鱼机会

算账讲究：到达超速不是一笔全款记头上，而是按近木点 JOI 捕获烧计费（Oberth 效应），公式拿朱诺号实测 542 m/s 校验过；出发超速单列一栏注明可交给火箭，报告里“总 ΔV 是多少、其中多少火箭出、多少探测器出”一目了然

皮实：进程池并行（CPU 直接拉满），个别序列崩了走错误通道单独记录，不拖累整轮；进度条带 ETA，重定向到文件时自动降级成逐行打印，两种姿势都能看进度

mga_scan_v2 是验证天问四的脚本，发射窗口收窄到 2028-2031，顺手把记账口径升级成了任务口径，想看 2029 附近窗口要付多少窗口税就跑它。

test 是 mga_scan 的冒烟测试脚本，改完代码先跑它，别拿 121 个序列直接试错。
